# 五子棋 AI 系统设计（wuzi-rl）

版本 v0.1（M0 初版）。与 `PLAN.md` 配套，随实现演进更新。

## 1. 设计原则

- **模块解耦**：规则引擎（纯逻辑、零 UI/AI 依赖）、界面、AI 决策、训练管线四层分离；训练与 GUI 完全解耦（GUI 只加载 checkpoint 做推理）。
- **一切 AI 逻辑自研**：仅依赖 PyTorch 张量原语（`Tensor` / `autograd` / `functional.conv2d` 等）与 NumPy；不使用任何第三方网络结构、预训练权重、RL 库。
- **可测性**：规则引擎为纯函数；MCTS 与训练管线各自可独立冒烟；所有随机性可注入种子。

## 3. 规则引擎（gomoku/board.py）

### 3.1 棋盘模型

- 15×15；坐标两种表示并互转：序号 `idx = r*15 + c`（0..224）与 `(r, c)`。
- 棋子：1 = 黑，2 = 白（内部对局值用 ±1，对外统一棋子编号）。

### 3.2 规则（v1）

- 黑先；自由规则（无禁手）；同一交点不可重复落子；任意方向连成五子即胜；棋盘落满且无五连为和棋。

### 3.3 胜负判定

- 落子后**增量检测**：仅检查经过该点的 4 条线（横、竖、主对角、副对角），每条线向两侧扩展至多 4 格，O(1) 完成。

### 3.4 API

```python
class Board:
    def __init__(self, size: int = 15): ...
    def reset(self) -> None: ...
    def is_valid(self, move: int) -> bool: ...
    def apply(self, move: int) -> int:      # 返回: 0进行中 / 1黑胜 / 2白胜 / 3和棋
    def undo(self) -> None:                 # 悔棋（历史栈）
    def winner(self) -> int | None: ...
    def legal_moves(self) -> list[int]: ...
    @property
    def to_play(self) -> int:               # 1 黑 / 2 白
    @property
    def move_count(self) -> int: ...
    def encode(self, player: int) -> np.ndarray:   # (4,15,15)，见 §5
    def symmetries(self, player: int) -> Iterator[tuple[np.ndarray, np.ndarray]]:  # 8 变换
    def key(self) -> str:                   # 局面规范化键（调试/统计复用）
```

### 3.5 对称变换

- 实现 D4 群全部 8 个 `(r,c) → (r',c')` 双射（恒等、旋转 90°/180°/270°、镜像×4），并预计算策略索引重排表（15×15 → 225）。
- 训练增强与 MCTS 复用同一实现；单测覆盖全部 8 变换的状态/策略一致性。

## 4. pygame 界面（gomoku/gui.py）

- **窗口**：棋盘区 15×15（线距 40px、边距留白；星位：天元、四隅星）；状态栏显示当前手、胜负、AI 思考状态。
- **交互模式**（主菜单 + 对局内，M2 已实现 1-4 模式；ESC 返回菜单）：
  - `1` 人 vs 人：本地双人。
  - `2` / `3` 人 vs AI：选边（人执黑 / 人执白），AI = 纯 MCTS，模拟数由 `--sims` 指定（低难度默认 200）。
  - `4` AI vs AI：观战模式。
  - 回放：待 M4 完善（读取对局记录逐步重放）。
  - 对局内：R 重开、U 悔棋（人机模式下悔棋仅限人类行棋时）。
- **线程模型**（已实现）：主线程渲染与事件；AI 推理在后台线程执行（`threading.Thread` + `queue.Queue` 回传着法），对局中显示“AI 思考中…”，禁止 UI 卡顿。
- **落子反馈**：上一步高亮；胜利时连线五子高亮。

## 5. 状态编码与动作空间

### 5.1 输入张量（4, 15, 15），当前玩家视角

| 通道 | 含义 |
|---|---|
| 0 | 当前玩家棋子位置 = 1 |
| 1 | 对方棋子位置 = 1 |
| 2 | 常数层：全 1（标记“轮到我”，提供方向信息） |
| 3 | 上一手落点 = 1（首步全 0；提供战术上下文） |

- 所有样本/推理统一“轮到谁”视角，保证数据自洽。

### 5.2 动作空间

- 策略输出 225 路；对非法点 mask 后 softmax。
- 价值输出 v ∈ [−1, 1]（当前玩家胜率映射）；目标 z = +1 胜 / −1 负 / 0 和。

### 5.3 对称一致性

- 对状态做 D4 变换时必须同步变换 π（索引重排）与 z（不变）；单测覆盖。

## 6. 神经网络（ai/net.py，自研结构）

### 6.1 结构

```
输入 (4, 15, 15)
  → Stem:  Conv3×3(4→256) + BN + ReLU
  → N × ResBlock(256): Conv3×3 + BN + ReLU + Conv3×3 + BN，残差连接
  → 策略头: Conv1×1(256→2) + Flatten + Linear(450→225)
  → 价值头: Conv1×1(256→1) + ReLU + Linear(225→256) + ReLU + Linear(256→1) + tanh
```

- v1 默认 N = 6；总参数约 **7.2M**（约 29MB fp32）。

### 6.2 自研性说明

- 结构由本项目自行设计；实现仅用 PyTorch 张量原语（`functional.conv2d/linear/batch_norm`、`autograd`），不引入任何第三方网络结构或预训练权重。
- **初始化**：卷积 Kaiming（He）初始化，BN 权重 1/偏置 0，输出头小方差——初始策略接近均匀、价值接近 0，保证早期搜索多样性。

## 7. MCTS（ai/mcts.py）

### 7.1 节点

- `N(s,a)` 访问次数、`W(s,a)` 累计价值、`Q = W/N`、`P(s,a)` 网络先验、子节点表、虚拟损失计数。

### 7.2 搜索流程（每步决策）

1. **Select**：从根沿 PUCT 选至叶子：`argmax_a Q(s,a) + c_puct·P(s,a)·√N(s) / (1+N(s,a))`（c_puct 默认 1.5，可配置）。
2. **Expand**：叶子为终局 → 以真实胜负值回传；否则网络评估得 (P, v)，展开子节点。
3. **Evaluate**：**批量叶子评估**——同一搜索树内的待评估叶子攒批（batch ≤ 64）统一送入 GPU 减少启动开销；评估中的节点用虚拟损失避免重复选择。
4. **Backup**：沿路径回传 v（按当前玩家视角翻转），累计 N/W。

### 7.3 决策输出

- 训练对局：前 15 步按 `π ∝ N^(1/τ)` 采样（τ = 1.0），之后 τ → 0（取访问最多者）；根节点先验注入 Dirichlet 噪声（α = 0.3，ε = 0.25）。
- 正式对弈：τ = 0 确定性 + 模拟数档位（低/中/高）。

### 7.4 纯 MCTS 基线（M2，无网络，已实现）

- **选择**：UCB1 `Q + c·√(ln N_parent / (1 + N_child))`，c = 1.4（config.c_ucb）。
- **展开**：懒展开（每次迭代仅展开一个子节点）；**邻域剪枝**——只展开与已有棋子切比雪夫距离 ≤ 1 的合法点（空盘退化为全部合法点），225 路分支下避免 UCB1 探索过宽。
- **模拟**：快速 rollout 至终局，候选集用**增量邻域集合**维护（落子时并入其 8 邻域，避免全盘扫描）；策略优先级：己方成五 > 堵对方成五 > 邻域均匀随机。
- **强制着**：`best_move` 先做确定性检查——己方一步成五必走、对方一步成五必堵，再进入搜索（消除搜索噪声对强制着的影响）。
- **回传**：价值 ±1/0 按玩家视角逐层翻转；着法取访问次数最多者。
- **实测基线**（M2）：vs 随机 100%（4-0）；vs 自研贪心启发式 0%（低模拟数）——随机 rollout 的纯 MCTS 需极多模拟才能匹敌手工战术知识，强度提升依赖 M3 神经网络评估。
- 用途：棋力下限基线 + 评估参照，不参与最终 AI。

## 8. 自对弈管线（ai/selfplay.py）

### 8.1 流程

- 每局：用“当前最佳”网络 + MCTS（训练档模拟数）双方对弈，记录每一步 `(编码状态, 访问分布 π, 终局值 z)`；z 以每步视角归一化。
- 增强：每样本做 8 种 D4 对称（状态与 π 同步变换）→ 样本量 ×8。
- 存储：`data/games/*.npz`（每局一个文件）；经验池保留最近 N 局（默认 500）滑动采样。

### 8.2 并发（v1 → v2）

- v1：单进程 + GPU 批量叶子评估（§7.2），预计 2–5 秒/局。
- v2（性能不足时启用）：多进程 worker（各自跑 MCTS、共享只读权重）+ 集中 GPU 评估服务（汇聚多 worker 的叶子请求成批）；接口预留，架构不变。

### 8.3 公平性

- 黑白对称增强天然平衡先手偏差；评估时强制双方换边。

## 9. 训练循环（ai/train.py）

### 9.1 目标与优化

- `L = (z − v)² − πᵀ log p + λ‖θ‖²`，λ = 1e-4。
- 优化器默认 AdamW（lr = 1e-3，wd = 1e-4）；连续 2 次未过评估门则 lr × 0.5；全部集中在 `config.py` 可调。

### 9.2 节奏

- 每 500 局自对弈后训练（batch 512，采样自经验池）；每 200 训练步触发评估门：新网 vs 当前最佳 200 局（强制换边），胜率 ≥ 55% 采纳，保存 `checkpoints/best.pt`，追加 `runs/history.csv`（迭代、胜率、损失）。

### 9.3 续训

- 经验池、checkpoint、runs 记录全部落盘 → 中断后一键续训。

## 10. 评估与基线（ai/arena.py）

- 协议：双方同模拟数（评估档 800/步或限时 2s/步），每组对战强制黑白交换。
- 基线：随机；贪心启发式（自实现：连五 > 活四/挡四 > 活三/挡三 > …… 的简单评分）；纯 MCTS（限时）。
- Elo：自实现简易 Elo（K = 32，初始 1500），正式评估自动更新 `runs/elo.csv`。

## 12. 性能实测（RTX 4060 Laptop，8GB，M3 实测）

网络 7.26M 参数（6 ResBlock × 256 通道），CUDA 12.6，fp32：

| 项 | 实测 | 说明 |
|---|---|---|
| 训练显存（batch 512，fp32 + AdamW） | ≪ 8 GB | 无显存压力 |
| 单样本前向 | 2.1 ms | — |
| 批量 64 前向 | 19.2 ms（≈0.3 ms/样本） | 叶子批量评估主力 |
| 自对弈吞吐（sims=200/步） | 11.0 s/局（66 步，167 ms/步） | 批量评估 + 树开销；v2 多进程可再除 4 |
| 训练一步（batch 512） | 576 ms | 每迭代训练步骤 ≈ 样本数/512 |
| 一迭代（500 局 + 训练） | 约 1.5–2 h（估算） | 自对弈为主导，可挂机长训 |

> v1 棋力目标总预算仍为 2–5 天 GPU 时间（数十迭代），M4 强化训练阶段执行。
